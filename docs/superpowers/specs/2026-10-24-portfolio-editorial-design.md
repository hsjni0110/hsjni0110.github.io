# 질문과 근거 중심의 포트폴리오 개편

사용자의 요청: 진부한 직무 선언 대신 호기심을 만드는 첫 문장, 깊은 사례, 선명한 채용 근거, 좋은 UX와 자연스러운 모션. 이전 평가의 정보 우선순위·반복·증거 문제를 반영하며 로컬에서 완성한다.

## 방향과 대안
- 채택: 질문형 에디토리얼. ‘끝났다’는 말의 조건을 묻는 첫 문장에, 생성 음성의 오류·기록의 빈틈·적재 결과 검증이 답하는 구성. 개발자 한석진이라는 직무 단서는 명시한다.
- 직무·기술을 나열하는 영웅 영역은 사용자가 진부하다고 평가. 과도한 3D·커서 추적·스크롤 제어는 읽기와 접근성에 불리해 배제.
- 밝은 종이색, 기존 청색을 강화한 포인트, 큰 타이포그래피, 번호·가느다란 선으로 리듬 형성. 기존 사진·실제 화면·로컬 폰트 유지.

## 정보와 증거
첫 문장과 세 질문 → 실무 경험 → SpeakText·ForgeSync 두 대표 사례 → 개발 중인 앱을 짧게 → 추가 학습 → 압축된 소개·교육·활동 → 연락.
SpeakText에는 서비스 소개·기여·관찰 결과·관련 PR을 짧게 연결. 실제 화면인 것처럼 꾸민 도식 금지.
ForgeSync의 실제 개선 전후 이미지를 전환할 수 있게 하고 무엇을 분리했는지 표시. 정확도 개선 주장 금지.
상세는 기존 제목·문장형 설명을 보존하되 강조할 핵심 판단·근거 링크로 읽기를 보조. 사용자가 제거한 상세 상단 요약·목차를 재도입하지 않는다.

## 모션·UX
초기 타이포그래피 진입 500ms 이내, 버튼·전환 150~250ms, 섹션 단위의 가벼운 진입. 작은 텍스트를 한 글자씩 숨기지 않는다. 텍스트는 기본적으로 보이며 JS가 실패해도 읽을 수 있다. IntersectionObserver는 관찰 시 Web Animations를 실행하고 한 번만 재생한다.
개선 전후는 네이티브 details 기반으로 JS 없이 작동한다. 키보드·touch 44px·prefers-reduced-motion·가로 넘침을 검사한다. 주소·메뉴·메일·PDF 링크는 유지한다.
