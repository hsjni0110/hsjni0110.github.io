## 원문 분할 처리에서 예상한 인물 연결 오류

소설에서 생성한 대사의 발화자를 작가가 확인하고 수정하는 기능 구현. 스크립트·음성 생성부터 발화자별 색 구분, 편집 화면과 일괄 수정 API까지 담당.

긴 원문을 나눠 처리할 때 이름·호칭 차이로 같은 인물이 여러 인물로 나뉘는 문제 예상. 인물마다 목소리가 바뀌거나 대사가 다른 인물에게 연결될 경우, 청자가 이야기를 따라가기 어려울 가능성.

## LLM 보완과 작가의 직접 수정 기능 도입

이전 등장인물 정보를 다음 생성에 전달하고 인물 ID로 연결하는 방식 적용. 이후 팀원들과 생성된 음성을 들으며 발화자 연결 오류 확인.

LLM의 정확도 개선만으로 오류를 없애기 어렵다는 팀의 판단. 작가가 등장인물 이름·목소리와 대사 연결을 확인하고 수정하는 기능 도입 결정.

## 발화자별 색 구분 제안과 화면·API 구현

- 스크립트 생성, 등장인물 동기화, 음성 생성 담당
- 이전 문맥과 인물 ID를 활용한 인물 연결 구현
- 등장인물 이름·목소리 선택과 대사 수정 기능 구현
- 잘못 연결된 대사를 찾기 위한 발화자별 색 구분 제안·화면 구현
- 여러 대사를 수정하는 일괄 수정 API 구현

작가 검토 기능은 팀의 공동 결정. 발화자별 색 구분 개선안과 해당 화면·API는 직접 제안·구현한 범위.

## 팀원들과의 음성 청취·편집 기능 점검

팀원들과 음성을 듣고 편집 기능을 사용하며 결과 확인. 색으로 발화자를 구분한 뒤 잘못 연결된 대사를 찾고 수정하기 편해졌다는 반응.

**팀 내부 사용의 정성적 피드백.** 실제 작가 대상 사용성 시험과 수정 시간의 정량 측정은 미실시.

공개 코드에서 확인 가능한 범위는 발화자별 색 구분, 문장별 편집, 복수 수정 요청 API.

## 실제 작가의 오류 탐색·수정 시간 검증 과제

LLM의 인물 생략·연결 오류는 잔존. 확인된 자료에는 인물 일관성을 자동 검증하는 전용 테스트가 없으며, 당시 검증 방식은 직접 음성 청취.

후속 과제는 실제 작가의 오류 탐색 성공 여부와 수정 시간 측정. 팀 내부 반응과 외부 사용자 검증의 구분.
