## 맥락

처음부터 동시성과 트랜잭션을 학습하기 위해 예약 도메인을 선택했습니다. 한정된 좌석에 여러 사용자가 동시에 예약하고 결제하는 상황에서 데이터 정합성을 어떻게 지킬지 탐구하고 싶었습니다.

## 판단

사용자가 결제하는 동안 다른 사람이 좌석을 가져가면 안 됩니다. 반대로 결제하지 않고 이탈한 사용자의 점유가 계속 남아도 다른 사람이 예약할 수 없습니다.

두 상황을 고려해 결제 전 임시 선점과 미결제 만료를 나눴습니다. 선점 기한 5분은 실제 데이터로 검증한 최적값이 아니라, 결제 시간을 주고 좌석이 오래 묶이지 않게 하려는 학습용 정책입니다.

## 실행

좌석을 잠그고 예약을 만드는 흐름과 이미 선점된 좌석의 거절을 구현했습니다. 예약은 대기 상태로 시작하고, 미결제 상태가 일정 시간을 넘으면 좌석을 해제하도록 했습니다.

예약 소유자와 결제 가능 상태를 확인하고, 결제 후 후속 처리를 이벤트로 연결하는 구조도 탐구했습니다.

## 확인

같은 좌석에 여러 작업을 제출하고 성공 건수를 확인하는 동시성 테스트 코드가 있습니다. 다만 이번 포트폴리오 조사에서 해당 테스트를 실행한 것은 아니며, 코드의 전제도 있어 특정 동시 사용자 수를 보장하는 성과로 제시하지 않습니다.

## 한계와 다음 단계

결제 이벤트 사이의 지연 때문에 선점 만료와 예약 확정이 겹칠 수 있다는 경계 상황은 당시 고려하지 못했습니다. 현재 확인한 코드에는 이 충돌의 우선순위를 보장하는 처리를 찾지 못했습니다.

이는 해결된 성과가 아닌 현재 구현의 한계입니다. 다음 단계에서는 어느 상태에서 만료를 허용할지 규칙을 명확히 하고, 결제와 만료가 겹치는 상황을 직접 재현해 검증해야 합니다.
