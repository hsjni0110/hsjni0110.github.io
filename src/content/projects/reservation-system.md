## 좌석 중복 예약과 미결제 점유 문제

고속버스 예약 시스템에서는 결제 전 좌석 선점과 5분 미결제 예약 해제를 구현했습니다. 한정된 좌석에 여러 사용자가 동시에 예약하고 결제하는 상황을 통해 동시성과 트랜잭션을 학습하려고 선택한 도메인입니다.

같은 좌석을 중복 예약하지 않는 것뿐 아니라, 결제하지 않고 이탈한 사용자가 좌석을 계속 점유하는 상황도 고려해야 한다고 생각했습니다. 결제할 기회를 보장하면서도 다른 사용자에게 좌석이 다시 돌아갈 수 있는 규칙이 필요했습니다.

## 결제 시간 확보와 5분 선점 기한

사용자가 결제하는 동안에는 다른 사람이 같은 좌석을 가져갈 수 없어야 한다고 봤습니다. **그래서 결제 전에 좌석을 임시 선점하고, 결제하지 않은 예약은 일정 시간이 지나면 만료시키는 방식을 선택했습니다.**

선점 기한은 5분으로 정했습니다. 결제할 시간을 주면서 미결제 좌석이 너무 오래 묶이지 않게 하려는 학습용 정책입니다. 실제 사용자의 결제 시간이나 이탈 데이터를 분석해 정한 최적값은 아닙니다.

## 좌석 잠금·예약 생성·미결제 해제 구현

예약 생성 과정에서는 좌석을 잠그고, 이미 선점된 좌석에 대한 요청은 거절하는 흐름을 구현했습니다. 예약은 대기 상태로 시작하며, 5분 동안 결제하지 않으면 해당 좌석을 해제하는 처리를 추가했습니다.

결제 요청에서는 예약 소유자와 결제 가능한 상태인지 확인하고, 결제 후 처리는 이벤트로 연결했습니다. 다만 결제 이후 이벤트 처리와 만료가 충돌하는 경우까지 해결한 구현은 아닙니다.

## 같은 좌석의 예약 성공 건수를 확인하는 테스트

같은 좌석에 여러 작업을 제출하고 예약 성공 건수를 확인하는 동시성 테스트 코드를 작성했습니다.

다만 보존된 테스트 코드만으로 실제 동시 사용자 수나 처리 성능을 입증할 수는 없습니다. 테스트의 실행 조건과 결과를 별도로 확인해야 하므로, 특정 사용자 수를 처리한다는 수치 성과로 제시하지 않았습니다.

## 결제 이벤트 지연과 선점 만료의 충돌

**결제 이벤트 지연과 선점 만료가 겹치는 상황은 당시 고려하지 못했습니다.** 결제 후 예약 확정을 반영하기 전에 만료 처리가 실행된다면, 두 처리 사이의 우선순위가 필요합니다. 현재 구현에는 이를 보장하는 규칙이 없습니다.

다음 단계에서는 어떤 예약 상태에서 만료를 허용할지 먼저 정의해야 합니다. 이후 결제와 만료가 겹치는 상황을 직접 재현해, 좌석 점유와 예약·결제 상태가 정해진 규칙을 지키는지 검증할 필요가 있습니다.
