## 맥락

백업 파일을 임시 DB에 복원하고 필요한 테이블을 조회해 결과를 기록하는 기능 구현. 복원 검증 성공 이후의 임시 DB 정리 실패도 별도로 표시.

DBMS의 데이터 보호·복구와 반복 관리 자동화를 위한 학습 프로젝트. AI와 시장·운영 사례를 조사해 가정한 문제이며, 실제 고객의 운영 요구를 받은 작업은 아님.

## 판단

백업의 목적은 장애 이후 데이터 복구. 파일 생성 여부와 별개로 실제 복원 가능성 확인 필요.

전체 데이터 일치 검증의 비용·복잡도를 고려해 임시 DB 복원과 필수 테이블 확인부터 구현. 이후 검증 수준을 높이는 순서로 범위 설정.

## 실행

복원 → 테이블 확인 → 결과 기록 구현. 임시 DB가 남을 경우의 공간 점유와 운영 영향을 고려해, 검증 성공과 정리 실패를 별도 상태로 기록.

비동기 작업은 별도 큐 대신 기존 DB에서 상태와 결과 관리. 요청이 적을 것으로 예상한 학습 규모에서 운영 부담을 줄이기 위한 선택. 부하 측정을 통한 용량 검증은 미실시.

## 확인

필수 테이블 존재·누락, 복원된 테이블 없음, 선택적 행 수 조회, 정리 실패를 다루는 단위 테스트 작성. DB 응답과 명령 실행은 대체 객체 사용.

해당 테스트의 검증 범위는 판정과 처리 순서. 실제 손상 백업의 운영 환경 복원과 대용량 부하 검증은 미실시.

## 한계와 다음 단계

원본·복원본 전체 데이터 일치와 대용량 복원 비용은 미검증. 현재 상위 처리 흐름에는 복원 실패 이후 임시 DB 정리가 항상 실행되지 않는 경로 잔존.

후속 과제는 실패 경로의 정리 보완과 데이터 검증 수준 확대. 별도 큐 도입은 실제 병목 확인 후 검토.
